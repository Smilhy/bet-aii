BET+AI WERSJA 403 — PONOWNY GŁĘBOKI RETEST PIPELINE
=====================================================

Podczas ponownego testu V402 znaleziono i naprawiono 4 dodatkowe luki spójności:

1. SERVER VALUE POLICY PARITY
   Server mirror nie obsługiwał PRICE_MOVE_AGAINST tak samo jak klient.
   Efekt: klient mógł hard-blockować typ, podczas gdy server mirror tego nie robił.
   V403 dodaje pełną zgodność tego guarda.

2. SERVER-AUTHORITATIVE FREEZE
   Endpoint record-fm-ai-system-pick wcześniej mógł przyjąć od przeglądarki:
   - market key,
   - decision,
   - probability / fair odds / edge / EV / reliability.
   V403 ponownie liczy server policy i sam wybiera canonical topFinal.
   Browser nie może już wymusić innego rynku ani ekonomiki typu.

3. FIRST-PUBLISHED ALWAYS WINS
   Istniejący rekord trackera jest teraz sprawdzany przed ponowną analizą.
   Aktualny drift/NO_BET nie może spowodować odrzucenia lub podmiany wcześniej
   zamrożonego market identity.

4. FAIL-CLOSED WHEN EXACT MARKET DISAPPEARS
   Jeżeli pełna analiza nie potrafi już znaleźć dokładnie zamrożonego rynku,
   market key pozostaje ten sam, ale action zostaje obniżone do NO_BET.
   Stary VALUE nie jest już bezwarunkowo przenoszony dalej.

Dodatkowo:
- open handshake sprawdza istniejący frozen record także wtedy, gdy bieżący scan
  został już obniżony do SMALL_EDGE/NO_BET;
- auto tracker używa market/decision zwróconego przez server-authoritative recorder;
- client/server przekazują priceMoveAgainstPp w tej samej polityce.
